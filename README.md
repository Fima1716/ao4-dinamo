# All Smiles · Динамо

Лендинг центра имплантации All Smiles у метро Динамо (Москва): имплантация All-on-4, цены, врачи, запись на консультацию.

Боевой адрес: **https://allsmiles.217-18-60-60.sslip.io** (временный домен sslip.io, своего домена у клиники пока нет).

## Что это технически

Статический сайт: HTML + CSS + JS, без сборки, без npm и фреймворков. Открыл файл, поправил, сохранил. Плюс маленький Node.js API для админки (принимает заявки и хранит правки текстов).

## Структура

```
index.html        главная, весь основной контент
style.css         база: палитра, кнопки, первый экран (.v1)
design.css        дизайн-слой: шрифты, шапка, карточки
sections.css      все секции ниже первого экрана
mobile.css        мобильная версия (до 760px): таб-бар, сторис, шторки
script.js         интерактив: формы, квиз, калькулятор, оттенки, модалка
mobile.js         мобильный интерактив: сторис, таб-бар, шторки

vrachi/<slug>/    страницы врачей (9 шт), общий стиль vrachi/vrachi.css
admin/            панель администратора (заявки, SEO, метрика)
policy/           политика обработки персональных данных
thanks/           страница "заявка принята"
docs/             образец договора (PDF с выделениями ключевых пунктов)
assets/           картинки: врачи, кейсы, бренды, иконки

js/editor.js      применяет правки из админки, работает на всех страницах
api/server.js     сервер админки (Node.js, живёт отдельно под pm2)
```

### Порядок подключения стилей

`style.css → design.css → sections.css → mobile.css`. Чем позже файл, тем выше приоритет. Первый экран обёрнут в блок `.v1` и имеет собственный стиль: любые его правила пишутся с префиксом `.v1`, иначе сломаются заголовки остальной страницы.

### Как устроены ключевые механики

- **Квиз** (`#quiz`): 4 вопроса и форма контакта. На десктопе сцена держит одну высоту, на телефоне берёт высоту текущего шага, переходы через View Transitions API (в старых браузерах просто мгновенная смена).
- **Формы**: все заявки уходят POST-ом на `/api/lead` и попадают в админку. После отправки - переход на `thanks/`.
- **Возврат на место**: при уходе на страницу врача или отправке заявки позиция на странице запоминается (sessionStorage) и восстанавливается при возврате.
- **Против прыжков прокрутки**: на мобильных отключён scroll-anchoring (`overflow-anchor:none` в mobile.css) - без него Chrome на Android дёргает страницу при скрытии адресной строки. Не удалять.
- **Админка**: `/admin/` (вход по паролю) - заявки, SEO, метрика, колтрекинг. Кнопка "Редактирование страницы" (или `?admin` к адресу) включает правку текстов прямо на странице. Правки хранятся на сервере в API и привязаны к положению элемента в разметке: **если изменить структуру блока, правки клиента в нём сбросятся к исходным**.
- **robots.txt** отдаётся не файлом, а из настроек админки: nginx проксирует `/robots.txt` на `/api/robots.txt`.

### На что обратить внимание

- Форма "Второе мнение" (загрузка плана лечения): файлы на сервер **не загружаются** - в заявку уходит только телефон, администратор связывается и запрашивает документы сам. Так задумано.
- Фото врачей и пациентов публикуются с их согласия - не заменять произвольно.
- Тексты медицинские: нельзя писать "гарантируем результат", "без боли", "навсегда". В подвале обязательна строка "Имеются противопоказания. Необходима консультация специалиста".
- В текстах используется короткое тире "–", не длинное.

## Деплой

Автодеплоя нет: пуш в GitHub ничего не выкатывает. Сайт выкладывается вручную по rsync.

### Что нужно один раз

1. **SSH-доступ к серверу**: ключ пользователя должен быть добавлен на `root@217.18.60.60` (сервер Ubuntu, nginx, файлы сайта в `/var/www/ao4-dinamo`, API в `/var/www/ao4-api` под pm2).
2. **rsync** (на macOS и Linux уже есть).
3. Проверить доступ: `ssh root@217.18.60.60 'echo ok'`.

### Последовательность выкладки

Из корня репозитория, по шагам:

```bash
# 1. Убедиться, что рабочее дерево чистое и ты на main
git status

# 2. Проставить версию стилям и скриптам (борьба с кэшем браузеров).
#    Правка временная, в репозиторий не коммитится.
v=$(git rev-parse --short HEAD)
sed -i '' -E "s#(href|src)=\"([^\"?:]+\.(css|js))\"#\1=\"\2?v=$v\"#g" index.html

# 3. Выложить. Сначала с --dry-run посмотреть, что изменится:
rsync -rlDz --checksum --delete --no-perms --no-owner --no-group --dry-run --itemize-changes \
  --exclude '.git' --exclude '.github' --exclude '.gitignore' \
  --exclude 'api' --exclude 'README.md' --exclude 'AGENTS.md' --exclude '.DS_Store' \
  --exclude 'node_modules' --exclude 'scratchpad' --exclude '*.code-workspace' \
  --exclude 'pravki' --exclude 'photozone' --exclude 'render-3d' --exclude 'All-Smiles-*.html' \
  ./ root@217.18.60.60:/var/www/ao4-dinamo/

# 4. Если список адекватный (нет неожиданных удалений) - то же без --dry-run.

# 5. Вернуть index.html к виду из репозитория:
git checkout -- index.html

# 6. Проверить, что выложилось:
curl -s https://allsmiles.217-18-60-60.sslip.io/ | grep -oE 'mobile\.css\?v=[0-9a-f]+'
# версия должна совпасть с git rev-parse --short HEAD
```

### Если менялся api/server.js

```bash
rsync -az api/server.js root@217.18.60.60:/var/www/ao4-api/server.js
ssh root@217.18.60.60 'pm2 reload ao4-api'
```

### Важные нюансы деплоя

- **HTML отдаётся с `Cache-Control: no-cache`** - если сайт показывает старое, значит просто не выложили, кэш браузера ни при чём.
- **Картинки и PDF, заменённые под старым именем, версионируются руками**: к ссылке в HTML добавляется `?v=2`, `?v=3` и т.д. (автоверсии получают только css и js).
- **fail2ban на сервере**: много SSH-подключений подряд может временно забанить IP (Connection reset / timeout на 22 порту). Лечится ожиданием 10-20 минут, не долбить повторными попытками.
- `--delete` в rsync удаляет на сервере всё, чего нет в репозитории (кроме исключений). Поэтому dry-run перед выкладкой обязателен.
- Папка `api` исключена из выкладки сайта: API живёт отдельно и хранит данные (заявки, правки, настройки) в JSON-файлах рядом с собой - их нельзя перетирать.

## При переезде на свой домен

Временный адрес `allsmiles.217-18-60-60.sslip.io` прописан в трёх файлах:

- `index.html` - canonical, og:url и og:image (абсолютные ссылки в шапке);
- `sitemap.xml` - все адреса страниц;
- `policy/index.html` - адрес сайта в тексте политики (5 упоминаний).

Порядок действий:

1. Направить A-запись домена на 217.18.60.60, добавить server_name в конфиг nginx
   (`/etc/nginx/sites-available/ao4-dinamo`) и выпустить сертификат certbot.
2. Заменить адрес во всех трёх файлах одной командой (подставить свой домен):

   ```bash
   LC_ALL=C grep -rl 'allsmiles.217-18-60-60.sslip.io' index.html sitemap.xml policy/index.html \
     | xargs sed -i '' 's#allsmiles\.217-18-60-60\.sslip\.io#новый-домен.ru#g'
   ```

3. Проверить глазами (`git diff`), закоммитить и выложить по обычному гайду выше.
4. В админке (вкладка "SEO и robots") проверить robots.txt - если в нём указан
   старый адрес в строке Sitemap, поправить там же.

Что должна получить принимающая сторона:

1. **Код** - доступ к репозиторию GitHub (перенос владельца или приглашение) либо

   только файлы проекта, без истории и локального мусора.
2. **Сервер** - доступ root@217.18.60.60 (или перенос на свой сервер). На сервере,
   помимо кода, живут данные, которых нет в репозитории: `/var/www/ao4-api/`
   (заявки `leads.json`, правки страниц `page_*.json`, настройки `settings.json`,
   секреты `data/secrets.json`) - при переносе забрать обязательно.
3. **Пароль админки** - передаётся отдельно, в репозитории его нет.
4. Этот README (деплой) и `AGENTS.md` (справочник по данным клиники и правилам текстов).
