# AGENTS.md — правила работы над проектом

Лендинги стоматологии **All Smiles** (центр имплантации у метро Динамо, Москва).
Файл для ИИ-агентов и разработчиков: как устроен проект, как коммитить, как деплоить.

---

## 1. Что это за проект

Статические лендинги без сборщика: чистые HTML, CSS и JS. Никаких npm, бандлеров и фреймворков — открыл файл и правишь.
Исключение: `api/server.js` — крошечный Node-сервис для инлайн-редактора текстов.

### Версии сайта

| Папка | URL | Что это |
|---|---|---|
| `/` (корень) | `/` | Наш дизайн целиком: 3D-протез на первом экране, лавандовая палитра, шрифт Onest |
| `variant1/` | `/variant1/` | Первые два экрана нашего дизайна |
| `variant2/` | `/variant2/` | Первые два экрана строго по прототипу клиента, визуал по гайдбуку, шрифт Nunito |
| `variant2-full/` | `/variant2-full/` | Полная страница по прототипу |
| `final/` | `/final/` | **Согласованная сборка:** первый экран от нашего дизайна + остальная страница по прототипу |

`final/` — основная версия для показа клиенту. Правки в первую очередь туда.

### Структура

```
assets/        фото и графика (общие для всех версий)
  brand/       логотип
  cases/       до/после наших пациентов (Е. Ш., Р. К., Т. Т.)
  doctors/     портреты врачей
  land/        кейсы и фото процесса с действующего лендинга клиники
  clinic/      фото клиники с открытия
  hero/        3D-рендер протеза для первого экрана
  shade/       фото улыбки и маска зубов для шкалы оттенков VITA
css/  js/      стили и скрипты корневой версии
api/           Node-сервис редактора (деплоится отдельно, в /var/www/ao4-api)
pravki/        референсы от клиента, в деплой не уходят
```

### Как наследуются стили

`final/style.css` → импортирует `variant2-full/style.css` → импортирует `variant2/style.css`.
Правка в `variant2/style.css` отражается во всех трёх. Если меняешь базу — проверь все версии.

Первый экран в `final/` обёрнут в `.v1` и использует свои CSS-переменные (шрифт Onest, тёмно-синий `--ink`), чтобы не конфликтовать с остальной страницей на Nunito. Любые правила первого экрана пиши с префиксом `.v1`.

## 2. Правила коммитов

### Формат

```
тип(область): краткое описание в повелительном наклонении
```

- **Строчные буквы**, без точки в конце, до 72 символов.
- Повелительное наклонение: «добавь», «почини», «убери» — а не «добавил» и не «добавляет».
- Описание на русском.

### Типы

| Тип | Когда |
|---|---|
| `feat` | новый блок, секция, функция |
| `fix` | починка бага — вёрстка поехала, скрипт падает, битая ссылка |
| `style` | только внешний вид: отступы, цвета, типографика |
| `content` | тексты, цены, фото, данные клиники |
| `refactor` | переписал код без изменения поведения |
| `perf` | ускорение, сжатие картинок |
| `docs` | README, AGENTS.md, комментарии |
| `chore` | конфиги, CI, зависимости, служебное |

### Области

`final`, `variant1`, `variant2`, `variant2-full`, `hero`, `quiz`, `editor`, `api`, `assets`, `ci`, `deploy`.
Если правка задевает всё сразу — область можно опустить.

### Примеры

```
feat(final): собери первый экран с протезом и страницу по прототипу
fix(hero): верни пропорции картинки протеза на мобильных
content(team): замени портреты Акчурина и Овсепяна местами
style(variant2): сделай строку про импланты жирнее
chore(ci): добавь деплой на сервер по пушу в main
```

### Тело коммита

Нужно, только когда непонятно «почему». Пиши причину, а не пересказ диффа:

```
fix(hero): верни пропорции картинки протеза на мобильных

Браузер брал высоту из атрибута height, потому что в CSS была задана
только ширина. Добавил height:auto.
```

### Что нельзя

- Мешать в одном коммите правку контента и переделку вёрстки.
- Коммитить `assets/brand/guidebook.pdf` (40 МБ) и любые секреты, ключи, пароли.
- Коммитить временные файлы `_t.html`, `_d.html`, `_m.html` — они в `.gitignore`.
- Пушить в `main` сломанную вёрстку: CI сразу выложит её на боевой сервер.

### Ветки

- `main` — то, что на сервере. Пуш в неё деплоит автоматически.
- Фичи: `feat/короткое-имя`, починки: `fix/короткое-имя`.
- Мержим через PR, если правка крупная. Мелкие — можно прямо в `main`.

## 3. Деплой

### Автоматический

Пуш в `main` → GitHub Actions (`.github/workflows/deploy.yml`) выкладывает сайт на сервер.
Руками ничего делать не нужно. Статус — во вкладке Actions.

### Что куда едет

- Сайт → `/var/www/ao4-dinamo/` на боевом сервере (хост и пользователь — в секретах репозитория)
- API редактора → `/var/www/ao4-api/`, перезапуск через `pm2 reload ao4-api` (только если менялся `api/server.js`)
- Не едут: `pravki/`, `README.md`, `AGENTS.md`, прототип, гайдбук, `.github/`

### Адреса

- Сайт: **https://allsmiles.217-18-60-60.sslip.io**
- Домен `ao4-dinamo.ru` пока смотрит на другой сервер — там действующий лендинг клиники на Тильде.

### Руками (если CI недоступен)

```bash
# DEPLOY_USER и DEPLOY_HOST лежат в секретах репозитория, спроси у команды
rsync -az --delete \
  --exclude '.git*' --exclude 'pravki' --exclude 'api' --exclude 'README.md' \
  --exclude 'AGENTS.md' --exclude 'All-Smiles-*' --exclude 'assets/brand/guidebook.pdf' \
  ./ "$DEPLOY_USER@$DEPLOY_HOST:/var/www/ao4-dinamo/"
```

## 4. Редактор текстов

На каждой странице подключён `js/editor.js`. Посетителю он подставляет сохранённые тексты, администратору даёт править их прямо на странице.

- Вход: добавь `?admin` к адресу страницы, затем пароль.
- Правки лежат на сервере в `/var/www/ao4-api/data/<страница>.json`, по файлу на страницу.
- Ключ правки — путь элемента в DOM. **Если переделываешь структуру блока, правки этого блока слетят** к исходному тексту из HTML. Предупреждай клиента перед крупным рефакторингом вёрстки.
- Пароль хранится в переменной окружения `EDITOR_PASSWORD` у процесса pm2. В репозитории его нет и быть не должно.

## 5. Как проверять правки

Сборщика нет, поэтому:

```bash
python3 -m http.server 8765   # затем http://localhost:8765/final/
```

Перед пушем прогляди руками:

- **1440×900** — основной десктоп;
- **390×844** — телефон;
- первый экран целиком помещается в высоту окна;
- формы: маска телефона, чекбокс согласия, кнопки открывают модалку, а не прокручивают вниз;
- картинки на месте, ничего не растянуто.

## 6. Правила по контенту

Это медицинский сайт, тексты под законом о рекламе:

- Нельзя: «гарантируем результат», «без боли», «навсегда», «лучшие в Москве» без подтверждения.
- Обязательно: «Имеются противопоказания. Необходима консультация специалиста» в подвале.
- У каждой формы — чекбокс согласия на обработку персональных данных.
- Цены помечай как пакет и указывай, что входит. Текущие: SNUCONE 189 000 ₽, Riellen's 349 000 ₽, Osstem 319 000 ₽ по запросу, Nobel Biocare — по расчёту.
